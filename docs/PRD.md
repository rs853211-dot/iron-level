## 1. Executive Summary

**Problem Statement.** Журналы тренировок сухие: рост рабочих весов не даёт обратной связи, поэтому регулярность падает. Универсальные приложения не знают конкретный зал (тренажёры Hammer Strength, Life Fitness, их расположение), и запись подхода занимает лишние шаги.

**Proposed Solution.** Фитнес-RPG для iPhone (PWA, офлайн, без бэкенда): персонаж растёт вместе с рабочими весами; XP, уровни, рекорды и недельные серии считаются из журнала. Приложение знает зал владельца (карта, каталог тренажёров) и ведёт по программе тренировок с календарём.

**Success Criteria** (**[Предложение]**, все измеримы из журнала `localStorage` и ручного учёта):

| # | KPI | Цель | Как измеряется |
|---|-----|------|----------------|
| K1 | Удержание: недели подряд с ≥2 тренировками | ≥ 8 из 12 недель после релиза v1.0 | `derive()`, серия |
| K2 | Выполнение плана: доля запланированных дней календаря, закрытых тренировкой | ≥ 75 % за 4 недели | `calPlan()` против журнала |
| K3 | Скорость записи: от открытия приложения до сохранённого первого подхода | ≤ 15 с, ≤ 5 касаний (замер секундомером на 10 тренировках) | ручной замер |
| K4 | Целостность данных: потерянные или повреждённые записи | 0 за любой период; восстановление из резервной копии успешно в 100 % случаев | `tests/backup.test.js`, ручной прогон раз в месяц |
| K5 | Офлайн: холодный старт в самолётном режиме после первого посещения | 100 % успеха, интерактивность ≤ 1 с | ручной тест на устройстве |

## 2. User Experience & Functionality

### 2.1 Персоны

1. **Владелец-атлет (основная, v1.0).** Тренируется в своём зале, 2–4 раза в неделю, пользуется iPhone, интерфейс на русском. Хочет видеть прогресс по весам и не тратить время на ввод в зале.
2. **Постоянный клиент зала (v2.0).** Тренируется в том же зале, ставит приложение по ссылке/QR. Нужна простая регистрация и понятный старт без знания 1ПМ.
3. **Тренер зала (v2.0).** Смотрит прогресс подопечных, не вводит данные за них **[TBD: нужны ли тренеру права на правку]**.

### 2.2 Пользовательские истории и критерии приёмки

Статус: ✅ реализовано · 🟡 частично · ⬜ не начато.

**US-1 (✅). Создание персонажа.** *Как новый пользователь, я хочу задать имя, пол, вес, рост, возраст, чтобы силовые нормативы считались под меня.*
- Профиль сохраняется в `localStorage` (`ironlevel.v1`); вес тела в пределах валидации **[TBD: границы не зафиксированы в коде, зафиксировать]**.
- На экране создания доступно «Восстановить из файла».
- После создания показываются 7 экранов `INTRO` один раз (флаг `ironlevel.v1.intro`).

**US-2 (✅). Запись тренировки.** *Как атлет, я хочу вносить подходы (вес, повторы) по упражнениям, чтобы вести журнал.*
- Вес ≤ 1000 кг (`WEIGHT_MAX`), повторы ≤ 100 (`REPS_MAX`); значения вне диапазона отклоняются с сообщением.
- Незавершённая тренировка сохраняется как черновик (`ironlevel.v1.draft`) и восстанавливается после закрытия вкладки; неизвестные упражнения из черновика удаляются без падения.
- Учитываются признаки упражнения: `bw` (вес тела + добавка), `per` (одна гантель), `plates` (блины на обе стороны), `assist` (противовес гравитрона).

**US-3 (✅). Геймификация без дублирования данных.** *Как атлет, я хочу видеть XP, уровень, рекорды, серии и достижения, чтобы чувствовать рост.*
- XP: подход +5, рекордный подход +25, завершённая тренировка +30, задание дня +15, 3-я и далее тренировка за неделю ×1,1.
- Порог уровня L→L+1 = `100 + 50·(L−1)` XP.
- Рекорд = лучший 1ПМ по Эпли `w·(1+r/30)`.
- Всё пересчитывается из журнала в `derive()`: удаление тренировки уменьшает XP. Производные значения не хранятся.
- Правила покрыты `tests/core.test.js`.

**US-4 (✅). Сила и ранги групп мышц.** *Как атлет, я хочу видеть силу каждой группы и её ранг, чтобы находить отстающие.*
- Сила 0–100 = лучший 1ПМ ÷ (вес тела × `t` упражнения), максимум 1.
- Ранги: Бронза 0, Серебро 25, Золото 50, Платина 70, Элита 90 (`groupRank()`).
- Группа «отдыхает», если нагружалась сегодня или вчера (`recovery()`).
- Силуэт персонажа (`figure()`) отражает силу групп через `muscleFill()`.

**US-5 (✅). Программы тренировок.** *Как атлет, я хочу выбрать программу и редактировать её, чтобы тренироваться по плану.*
- Встроенные: фулбади, верх-низ, пуш-пул-ноги (`PROGRAMS`); следующий день считается из журнала в `nextDay()`.
- Свои программы и правка встроенных; лимиты `MAX_PROGS`/`MAX_DAYS`/`MAX_SLOTS`; подходы 1–10; «Вернуть исходную».
- Скрытое в «Мой зал» упражнение заменяется следующим вариантом или упражнением той же группы (`buildDay()`).
- Тесты: `tests/programs.test.js`.

**US-6 (✅). Календарь.** *Как атлет, я хочу видеть сделанные, плановые и пропущенные дни.*
- Месяц сеткой с понедельника, полоса на 7 дней, карточка дня, выбор дней тренировок (`profile.schedule`, 1–7).
- Шесть различимых состояний дня: сделано, рекорд, по плану, пропущено, отдых, сегодня.
- «Пропущено» появляется только после первой записанной тренировки.

**US-7 (✅). Карта зала.** *Как атлет, я хочу открыть карту зала и увидеть, где тренажёры сегодняшних упражнений.*
- Полноэкранная карта: перетаскивание, щипок, колесо, двойное касание; подписи ≥ 11 px.
- Жёлтая рамка у тренажёров упражнений дня, нажатие показывает упражнения, «Начать»/«Добавить» создаёт или дополняет тренировку.
- Редактор разметки, экспорт/импорт JSON (`parseMap()`, `tests/map.test.js`).

**US-8 (✅). Резервная копия.** *Как атлет, я хочу выгрузить и загрузить все данные, чтобы не потерять их при смене телефона.*
- JSON `{app:"iron-level", version:3, …}`; версии 1 и 2 читаются; загрузка заменяет данные только после подтверждения.
- Невалидный файл не изменяет данные (`parseBackup()`, `tests/backup.test.js`).

**US-9 (✅). Офлайн и установка.** *Как атлет, я хочу ставить приложение на «Домой» и пользоваться в зале без сети.*
- `sw.js`: cache-first, обновление в фоне; `manifest.webmanifest` и иконки 180/192/512.
- `navigator.storage.persist()` запрашивается при старте.

**US-10 (⬜, v1.1). Экспорт в читаемый вид.** *Как атлет, я хочу выгрузить историю в CSV, чтобы анализировать её в таблице.* Критерий: одна строка = один подход; колонки дата, упражнение, вес, повторы, 1ПМ; открывается в Numbers/Excel без ручной настройки кодировки (UTF-8 BOM).

**US-11 (⬜, v1.1). Графики прогресса.** *Как атлет, я хочу видеть график 1ПМ упражнения по времени.* Критерий: период 4 недели / 3 месяца / год; точки = тренировки; отрисовка ≤ 100 мс на 500 тренировках; цвет данных только жёлтый `#f2c230` по правилам дизайна.

**US-12 (🟡, код готов, ждёт настройки Supabase). Аккаунты и синхронизация.** *Как пользователь, я хочу входить с разных устройств, чтобы данные были одинаковы.* Вход кодом из письма; приложение работает из `localStorage`, облако — вторая копия; слияние по времени сервера с надгробиями удалений (`cloudMerge()`, `tests/cloud.test.js`); RLS — каждый видит только свои строки (`supabase/schema.sql`); регион EU (Франкфурт). Настройка: `docs/supabase-setup.md`. Для клиентов зала нужен свой SMTP **[TBD]**.

**US-13 (⬜, v2.0). Режим тренера и рейтинг зала.** *Как тренер, я хочу видеть прогресс подопечных.* Критерии и приватность (согласие подопечного на показ данных) определить до разработки **[TBD]**.

### 2.3 Non-Goals

- Нативное iOS-приложение, App Store, монетизация — вне v1.x (см. §5, фаза v2.0+, **[TBD]**).
- ИИ-тренер — **отложен**; в v1.x остаётся заглушка «работает, когда страница открыта в Claude» либо скрывается **[Предложение: скрыть, чтобы не показывать нерабочую функцию]**.
- Подсчёт калорий, питание, шаги, интеграция с Apple Health / носимыми устройствами.
- Кардио-учёт: тренажёры кардио на карте есть, записей по ним нет (вид `idle`).
- Социальная лента, комментарии, соревнования между пользователями до v2.0.
- Смена языка интерфейса: только русский, обращение на «ты».
- 3D-вид карты и отдельный вид «Силовая зона» — решение владельца, не возвращаться.
- Медицинские рекомендации; приложение не заменяет тренера или врача.

## 3. AI System Requirements

**Статус: вне scope v1.x (отложено владельцем).** Ниже — только условия, при которых функцию можно вернуть, чтобы решение не пришлось выводить заново.

- **Предпосылка:** бэкенд-прокси к Claude API; ключ никогда не лежит в клиенте (правило проекта).
- **Данные в запросе:** минимально необходимые (агрегаты по группам, последние N тренировок). Имя и точные параметры тела не передаются **[Предложение]**.
- **Evaluation (когда включится):** набор из 50 эталонных ситуаций (застой веса, пропуск недели, перетренированность одной группы); безопасность: 0 рекомендаций веса, превышающих +10 % к последнему рабочему без пояснения; доля ответов, прошедших ручную проверку владельцем, ≥ 90 %; задержка p95 ≤ 5 с.

## 4. Technical Specifications

### 4.1 Архитектура (текущая)

```
iPhone Safari / PWA
 └─ index.html  (CSS + разметка + ванильный JS, без сборки и зависимостей)
     ├─ derive()            журнал → XP, уровни, рекорды, серии, достижения
     ├─ PROGRAMS / PRM      каталог программ + profile.programs
     ├─ EX / ZONES          каталог упражнений и зон зала
     ├─ GYM_MAP / GYM_MODELS / GM_ICON   карта зала, модели, иконки
     └─ store.local()       обёртка над localStorage
 ├─ sw.js                   cache-first, обновление в фоне
 ├─ manifest.webmanifest, icons/, fonts/ (Inter 400–600, OFL, cyrillic+latin)
 └─ localStorage: ironlevel.v1 · .draft · .intro · .map · .broken
```

Принципы:
1. Источник истины — журнал тренировок; производные значения не хранятся.
2. Нет внешних ресурсов и сетевых запросов при работе.
3. **id упражнений не переименовываются** (по ним читаются сохранённые тренировки).
4. При изменении модели данных поднимается `BACKUP_V`, `parseBackup()` читает все прошлые версии.

### 4.2 Модель данных

- `profile`: `{name, sex, bw, height, age, gym, hidden[], custom[], program, programs[], schedule[], createdAt}`
- `workout`: `{id, date: "YYYY-MM-DD", t, exercises: [{ex, sets: [{w, r}]}], prog?, day?}`
- Резервная копия: `{app, version: 3, exportedAt, profile, workouts}`

### 4.3 Нефункциональные требования

| Область | Требование |
|---|---|
| Производительность | Холодный старт из кэша ≤ 1 с на iPhone **[TBD: целевая модель]**; ввод подхода без заметной задержки (≤ 100 мс отклик) |
| Размер | `index.html` — сейчас ≈ 190 КБ; порог для пересмотра архитектуры (разбиение на модули) — 400 КБ **[Предложение]** |
| Доступность | Кнопки ≥ 44 px; подписи карты ≥ 11 px; контраст текста WCAG AA на `#0d0d0c`; `prefers-reduced-motion` учитывается **[проверить]** |
| Совместимость | iOS Safari, актуальная и предыдущая мажорная версия **[TBD: минимальная]** |
| Надёжность хранилища | Ошибка записи показывает сообщение; битый JSON не сбрасывает пользователя (копия в `ironlevel.v1.broken`); записи без `id` и даты отбрасываются |
| Тестирование | `node tests/run-node.mjs` (Node 22, без зависимостей) в CI `.github/workflows/test.yml`; релиз только при зелёном CI |
| Дизайн | «true-black flat» (`docs/design-direction.json`): фон `#0d0d0c`, единственный акцент `#f2c230` для данных, белая главная кнопка, шрифт Inter, без теней/blur/эмодзи |

### 4.4 Интеграции

- **Сейчас:** GitHub Pages (деплой `.github/workflows/pages.yml` при пуше в `main`). Внешних API нет.
- **v2.0 [TBD]:** бэкенд (аккаунты, синхронизация), выбор стека не сделан.

### 4.5 Безопасность и приватность

- Все данные хранятся локально на устройстве; наружу не передаются.
- Любой текст пользователя выводится через `esc()`; импортируемые файлы (резервная копия, карта, программы) проходят валидацию (`parseBackup()`, `parseMap()`, `cleanPrograms()`).
- Репозиторий публичный: `machines/` и `Geräte/` (фото с сайтов производителей) в `.gitignore`, на Pages их нет; приложение работает без них (`modelImg()` скрывает картинку).
- **GDPR (зал в Берлине, v2.0):** при хранении данных клиентов на сервере нужны правовое основание, согласие на показ тренеру, право на удаление и экспорт, политика конфиденциальности **[TBD: юрист/владелец зала]**. В v1.x серверных данных нет.
- Риск Safari: `localStorage` может быть очищен системой при нехватке места или после ~7 дней без использования в обычной вкладке; митигируется установкой на «Домой», `storage.persist()` и регулярной резервной копией (см. R1).
